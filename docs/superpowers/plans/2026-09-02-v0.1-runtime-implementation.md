# Agent Supervisor Runtime V0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the V0.1 local supervisor runtime that executes a durable `Task -> Worker -> Result -> Review -> PASS | REVISE | ASK_USER` loop with Codex Exec, file-backed state, policy-controlled retries/revisions, and replaceable adapters.

**Architecture:** A TypeScript orchestration core depends only on `SupervisorAdapter`, `WorkerAdapter`, `StateStore`, and `PolicyEngine` contracts. V0.1 ships `CodexExecWorker`, `MockSupervisorAdapter`, and `FileStateStore`; ChatGPT Desktop triggering remains an adapter boundary for a later version. Every durable phase is persisted before the next side effect, and worker output is supplemented with machine-observed evidence.

**Tech Stack:** Node.js 20+, TypeScript 5.x, ESM, npm, Zod for runtime schemas, Commander for CLI parsing, Vitest for tests, Node `child_process`/`fs/promises` for execution and storage.

**Spec:** `docs/superpowers/specs/2026-09-02-agent-supervisor-runtime-design.md`

## Global Constraints

- First supported environment: Windows 10/11, PowerShell 7, Node.js 20+.
- TypeScript is the primary implementation language; core code should remain cross-platform where practical.
- V0.1 must not depend on ChatGPT Work, Full MCP, ChatGPT Desktop automation, GitHub orchestration, Codex App Server, a database server, a cloud service, or distributed execution.
- Core orchestration must not know ChatGPT Desktop or Codex internals; it depends only on contracts.
- Supervisor side effects are prohibited: shell/filesystem/git writes remain behind worker adapters.
- Technical retry and substantive review revision are independent counters.
- Default `maxRevisions` is 3; default `maxWorkerRetries` is 2.
- Invalid supervisor control data transitions to `BLOCKED` with reason `SUPERVISOR_RESPONSE_INVALID`.
- Repeated unresolved review findings block further automatic revisions after the same fingerprint persists through one attempted revision.
- No sensitive credentials are stored in repository configuration.
